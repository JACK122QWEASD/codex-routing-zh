**无论用户第一条消息说什么（打招呼、闲聊、提问都算），第一条回复只输出【第 1 问】，然后停下等用户回答。**

**铁律：一次只问一个问题。用户回答后才能问下一个。禁止把 ②③ 和 ① 捆在一起，禁止先回答问题或寒暄。**
唯一例外：用户明确说"不用调度模式／直接做"。

### 第 3 问确认后

- 配置**写回** `.route-state.json`（密钥禁止写入）。
- 用户消息里已含具体任务 → 读取 **`{{PROJECT_ROOT}}/agent.md`**，按其中「第 4 步」输出【任务分配方案】表格，**等用户说"执行"才动手**。
- 没有任务 → 回复"配置完成，把任务发我"。
- 定级时再读同目录 `rubric.md`；派发弱模型时读 `weak-channel.md`。
- **弱档若是推理模型，必须关思考**（请求体加 `"thinking":{"type":"disabled"}`），否则 88% token 烧在推理上。
- **W 档子任务必须批量派发**：写进一个 shell 脚本一次并行跑完，强档只做"写脚本 + 看校验退出码"两次决策。禁止逐个派发（实测：逐个 = N 轮强档推理，5 个子任务要 7 分钟；批量 = 2 轮，同样任务 1–2 分钟）。
- **校验用确定性命令**（`node --check` / `node --test` / `grep -c` 等），别用眼睛看弱模型输出。
- **批量派发前先 canary 探测**：先发一个最小探针确认弱档通道通不通；不通就直接升档，别浪费整批。
- **合并也脚本化**：`.scratch` 结果用脚本合并 + 校验命令，强档只看退出码，别逐个读文件。
- **派发前先查 `prompts.md` 的模板**，高频任务直接用（改名/补注释/写测试/格式转换/翻译），别临场现写 prompt。
- **可逆任务必跑回译校验**（`tools/roundtrip.py`，零 token），能抓住"形状对内容错"。
- **执行时按 agent.md 的「派发执行清单」逐项打勾**（canary → 自包含脚本 → 并行 → 校验 → merge.py 合并 → 收尾报告 → 快照），缺一项即违规。
